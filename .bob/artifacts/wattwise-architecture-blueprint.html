4 · Agent Decision Logic (Request Routing)
User sends chat message
→
POST /api/chat → prepend SYSTEM_PROMPT + history → LLM → stream reply → append to history
User edits appliance watts/hrs
→
Browser-local recalculate() fires instantly — zero network, zero LLM cost
User clicks "Ask WattWise"
→
Calculator data serialised → natural-language prompt → injected into chat → POST /api/chat
User clicks "Generate Tips"
→
GET /api/tips → LLM with JSON schema instruction → regex extract → render 5 tip cards
User clicks "Clear Chat"
→
DOM cleared (keep welcome) → DELETE /api/session/:id → history array reset
LLM returns error / timeout
→
Typing indicator removed → error bubble rendered → send button re-enabled → user can retry

8 · Security Considerations
🔑
API Key ProtectionKey stored in .env (git-ignored). Never in source. Standalone mode stores in localStorage only — never transmitted to any third party.
🛡️
XSS PreventionAll user input and LLM output HTML-escaped before injection. renderMarkdown() sanitises & < > before processing.
🚦
Input ValidationServer validates required fields (message, sessionId). Calculator validates array type. Non-numeric inputs default to 0 safely.
🔒
Transport SecurityAll Groq API calls over TLS 1.3. CORS enabled for local development. Production should restrict CORS origin.
📏
Context Window LimitSession history capped at 20 messages to prevent token overflow and unbounded memory growth.
⚠️
Error IsolationAll API calls wrapped in try/catch. Errors surface as chat bubbles — never crash the UI. Server returns structured error JSON.
